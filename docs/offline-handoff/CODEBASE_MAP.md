## 4. Gotchas found during the build

Append entries as `- [Phase N] fact. Consequence and what we did.`

- [Explore] Opening the app offline logs the user out (`AuthContext.getInfos` catch). Fixed in Phase 1 (D16).
- [Explore] The web History tab is empty when self-hosted without a licence (D15).
- [Phase 0] `expo prebuild` re-applies drift that upstream hand-edited out of the committed native files: Android
  `styles.xml` theme, the iOS camera usage string, an NFC `NDEF` entitlement, and `EXUpdatesRuntimeVersion`. After
  every prebuild, revert those hunks (the command is in the root `CLAUDE.md`) and commit only the intended diff.
- [Phase 0] The committed iOS project was signed by upstream's team `KXW8RH26AN` as `com.cmms.atlas`. `app.config.ts`
  now reads `APPLE_TEAM_ID` / `IOS_BUNDLE_ID`. The demo uses `4NZGXQRKBG` / `com.offlineprotocol.atlasdemo`, and the
  committed pbxproj carries those values. Prebuild without the env vars reverts to upstream's.
- [Phase 0] Xcode 27 doesn't ship `Simulator.app` where Expo CLI 53 looks, so `expo run:ios` fails with "Can't
  determine id of Simulator app", even with `--device`. Build with `xcodebuild` and install with `devicectl`
  (root `CLAUDE.md`).
- [Phase 0] Xcode 27 rejects pod targets whose deployment target is below 15.0 (several resource bundles say 9-13).
  Fixed in `plugins/ios/withXcode27PodsDeploymentTarget.js`, which raises them to 15.1.
- [Phase 0] `expo run:android --device` takes the device name (`adb devices -l` model, e.g. `SM_M176B`), not the
  serial.
- [Phase 0] No real Firebase config exists, but the committed native projects require `GoogleService-Info.plist`
  and `google-services.json`. `scripts/offline-demo/firebase-stub.sh` writes gitignored placeholders. The iOS API
  key must be 39 chars starting with `A`, or Firebase raises at launch. Analytics and push don't work, and the demo
  doesn't need them.
- [Phase 0] npm 12 skips dependency install scripts by default, so the SDK's `prepare: tsc` doesn't run on
  `npm install` in `mobile/`. Run `npm run build` in the SDK yourself.
- [Phase 0] Atlas has no "create user" endpoint. With `INVITATION_VIA_EMAIL=false`: `POST /users/invite`, then
  `POST /auth/signup` with the invited email and `role: {id}`. Signup without an invite returns 500. Signup puts the
  access token in `message`. Passwords need 12+ characters. `PATCH /tasks/work-order/{id}` needs `options: []`
  on every task, or re-runs return 500.
- [Phase 0] Unauthenticated calls (signin/signup) are limited to 20/min and 80/hour per IP. Repeated seeding can hit
  this; restart the API to reset the in-memory limiter.
- [Phase 0] The API Dockerfile re-downloaded every Maven dependency on each build (about 10 min). A BuildKit cache
  mount on `/root/.m2` makes rebuilds incremental.
- [Phase 0] Homebrew's `maven` runs on its own JDK 27, and Lombok then fails with `TypeTag :: UNKNOWN`. Always run
  `mvn` with `JAVA_HOME=$(/usr/libexec/java_home -v 17)`.
- [Phase 0] Two SDK apps on one phone publish the same GATT service UUID on the same radio. A peer connecting to
  that phone can read the other app's identity characteristic and bind the link to the wrong `off1…` address, which
  stalls delivery and causes neighbour flapping. Uninstall other SDK apps from demo phones (runbook).
- [Phase 0] SDK fix (`atlas-demo` a54b383d): after an iOS Bluetooth off/on, the iPhone advertised with no GATT
  service behind it (stale `isGattServiceReady`), and it never reported `bleStatusChanged(true)` because power-on
  only left the `.starting` state, not `.unavailable`. The result was that the iPhone received but never sent.
  Both are fixed in `ios/BleManager.swift`. Still open: `stop()` returns early in `.unavailable`.
- [Phase 0] SDK fix (`atlas-demo` 36415b01): iOS gets a new random BLE address on every Bluetooth power-cycle.
  Android kept redialling the old address. When it gave up, it reported the live peer lost and wiped the mapping
  the new link used. Fixed in `CentralGattClient.kt` and `MeshConnectionRegistry.kt`, with `StaleAddressRegistryTest`.
  SDK JVM tests: `cd bindings/react-native/android-ci-harness && JAVA_HOME=$(/usr/libexec/java_home -v 17)
  ~/.gradle/wrapper/dists/gradle-8.10.2-bin/*/gradle-8.10.2/bin/gradle :offlineprotocol:testDebugUnitTest`.
- [Phase 0] SDK Swift/Kotlin changes need only an app rebuild (`xcodebuild` / `expo run:android`), not
  `build:uniffi:*`. That's only for Rust changes.
- [Phase 0] The SDK logs "Dropped a '<event>' event: it arrived before any listener was registered", even though the
  listener is attached before `start()`. It's harmless for our events, which all arrived.
- [Phase 0] Each phone's JS console detaches from Metro after a lock or force-quit, so later `console.log` lines stop
  arriving. Read Android from `adb logcat | grep ReactNativeJS`. On iOS, read the Diagnostics screen.
- [Phase 0] The office has about 100 BLE advertisers ("dense network" filtering in the Android logs). Discovery and
  delivery were fine anyway, but note it when timing anything.
- [Phase 0] The Metro watch on the SDK makes watchman watch the whole SDK repo, Rust `target/` included, and it
  logs "Recrawled" warnings. They're harmless.
