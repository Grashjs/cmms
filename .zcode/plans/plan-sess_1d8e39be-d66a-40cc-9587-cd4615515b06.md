## Schritte

### 1. Quellen kopieren
- `AssetTrace/docs/logo_v4.png` → `docs/logo_v4.png`
- `AssetTrace/apps/web/scripts/gen-logo-assets.ps1` → `frontend/scripts/gen-logo-assets.ps1`
- `AssetTrace/docs/OEKOSYSTEM-BRANDING.md` → `docs/OEKOSYSTEM-BRANDING.md` (Doku der 4 Fallen, damit hier ebenfalls nachlesbar)

### 2. `.gitignore` ergänzen
Die Bildmarke (`docs/logo_v4.png`, mehrere MB) ist laut Setup git-ignoriert zu halten. Aktuelle `.gitignore` fängt sie nicht ab. Ergänzen:
```
# Bildmarke des Ökosystems (groß, git-ignoriert wie in AssetTrace)
docs/logo_v4.png
```
(Die erzeugten `logo-mark.png` / `logo-tile.png` in `public/` bleiben getrackt — sie sind klein und gehören ins Image. Existierende `logo`-Regeln werden nicht kollidieren, Pfade sind `docs/` bzw. `public/`.)

### 3. Eine isolierte Rendering-Änderung am Skript
Zweck: transparente Ecken für `icon.png` (dein Abnahmekriterium), ohne die 4 Fallen zu berühren.
- In `frontend/scripts/gen-logo-assets.ps1`: den Hintergrund-`<rect … fill="#ffffff"/>` auf `fill="none"` setzen. Die `rx`-Rundung bleibt erhalten (für den Fall, dass später doch eine Kachel gewünscht ist), nur die Füllung entfällt.
- Nichts an viewBox, `$SW`, `$STROKE`, `InvariantCulture`, Browser-Args, `Width -ne 512`-Check ändern.
- Hinweis dokumentiert im Skript-Kommentar: diese Abwandlung erzeugt transparente Ecken; `apple-icon.png` ist dadurch auf iOS-Home-Screen keine geschlossene Kachel mehr (bewusst in Kauf genommen).

### 4. Skript für `frontend/` ausführen
Das Skript leitet `public/` und `src/app/` aus `$PSScriptRoot` (= `frontend/`) ab. `frontend/src/app/` existiert nicht → vom Skript **nicht** selbst angelegt (es schreibt nur Dateien). Daher:
- `frontend/src/app/` anlegen.
- Aufruf aus `frontend/`:
  `pwsh scripts/gen-logo-assets.ps1 -Accent blau -LogoSource ..\docs\logo_v4.png`
- Erwartete Outputs:
  - `frontend/public/logo-mark.png` (512² Marke)
  - `frontend/public/logo-tile.png` (512² weiße Rundkachel + Marke = og:image)
  - `frontend/src/app/icon.png` (512² Badge, transparente Ecken, Akzent blau)
  - `frontend/src/app/apple-icon.png` (180² Badge)
  - `frontend/src/app/favicon.ico` (16/32/48/64, 4 Entries)

### 5. Outputs nach `home/` verteilen (Landing-Seite mitziehen)
`home/` ist Next.js mit `home/app/` (nicht `src/app/`). Das Skript zielt auf `src/app/`, deshalb verteile ich die erzeugten Dateien manuell:
- `frontend/public/logo-mark.png` → `home/public/logo-mark.png`
- `frontend/public/logo-tile.png` → `home/public/logo-tile.png`
- `frontend/src/app/icon.png` → `home/app/icon.png` (Next.js file convention)
- `frontend/src/app/apple-icon.png` → `home/app/apple-icon.png`
- `frontend/src/app/favicon.ico` → `home/app/favicon.ico` + `home/public/favicon.ico`
- Badge-Icons für die PNG-Links: `icon.png` herunterskalieren auf `home/public/favicon-16x16.png` und `home/public/favicon-32x32.png` (mit demselben HighQualityBicubic-Ansatz wie im Skript, per kurzem pwsh-Snippet, damit die PNG-Links auf das Badge zeigen).
- Überflüssig gewordene `frontend/public/favicon-16x16.png` / `-32x32.png`: diese zeigen aktuell auf die alte Marke. Da das Badge jetzt über `src/app/icon.png` (Next.js-respektive CRA-eigene Konvention) läuft, update ich die PNG-Links in `frontend/public/index.html` auf das Badge.

### 6. PNG-Links auf Badge umbiegen („nicht auf die Marke")
Gemäß Branding-Doc müssen die `<link rel="icon" type="image/png">` auf das **Badge** zeigen, weil Browser PNG über `.ico` bevorzugen.
- **`frontend/public/index.html`**: die beiden PNG-Icon-Links (`favicon-32x32.png` / `favicon-16x16.png`) durch Badge-basierte PNGs ersetzen (neu erzeugte `favicon-32x32.png` / `favicon-16x16.png` aus dem Badge in `frontend/public/`), so dass Tab das Badge zeigt.
- **`home/app/[locale]/layout.tsx`**: `icons.icon`-Array bleibt strukturell, aber die PNG-Einträge zeigen auf Badge-PNGs in `home/public/`. Den AssetTrace-`title`/`baseUrl`/`assettrace.org`-Text **unangetastet** lassen (separate Baustelle, gewählt).

- `icon.png`: Mitte Akzentfarbe `#1D477D`, Ecken transparent → visuell prüfen (Bild-Lesen via Read auf `frontend/src/app/icon.png`).

- PNG-`<link>`s in `frontend/public/index.html` und `home/.../layout.tsx` zeigen auf Badge-Pfade.
